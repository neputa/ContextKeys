# ContextKeys

Thunderbird のキーボードショートカットを、今見ている画面に応じて確認できるようにするためのプロトタイプ拡張機能です。

## 目標

- Windows を優先とした Thunderbird 向け拡張機能の開発を進める
- まずはメール一覧画面に限定したプロトタイプを作る
- 既定ショートカット `Ctrl+Shift+H` でショートカット一覧を表示できるようにする
- その後、他の画面や構造を段階的に拡張する

## 現在の進行状況

このワークスペースには、メール一覧向けの最小プロトタイプとして次の構成を作成済みです。

- `manifest.json` : WebExtension の定義
- `background.js` : `Ctrl+Shift+H` を受け取り、ポップアップ形式のダイアログを開く処理
- `shortcut-dialog.html` : 一覧表示の UI
- `shortcut-dialog.css` : ダイアログの見た目
- `shortcut-dialog.js` : データ読み込みと検索機能
- `data/shortcuts.json` : メール一覧向けのショートカット定義

## 実装方針

### 1. ブラウザ拡張機能の基本構成

初期段階では、Thunderbird の WebExtension として最小限の構造を持つようにします。

- `manifest.json` に `commands` を定義して `Ctrl+Shift+H` を割り当てる
- `background.js` で command を検知して画面を開く
- `shortcut-dialog.html` に一覧の UI を持たせる
- `data/shortcuts.json` にはショートカット定義を外出しする

### 2. まずはメール一覧のみを対象にする

ユーザーの要望どおり、MVP はメール一覧のみを対象にし、以下を確認します。

- `Ctrl+Shift+H` で一覧が開くか
- 画面内で検索できるか
- キーと説明が見やすいか
- 画面遷移や操作に問題がないか

### 3. コンテキスト判定は後段で拡張

今回のプロトタイプでは、まずメール一覧用のショートカット定義を持ち、将来の拡張を見据えた構造にします。

今後は以下を順に強化します。

- 共通ショートカット
- メール一覧
- メッセージ表示
- メール作成
- その他ラベル

## 実行の想定フロー

1. Thunderbird にこのアドオンを読み込む
2. メール一覧画面を表示する
3. `Ctrl+Shift+H` を押す
4. ダイアログが開いてショートカット一覧が見える
5. 検索ボックスで関連項目を絞り込める

## Thunderbird への読み込み手順（現行の正確な流れ）

最新のテーマと公式チュートリアルでは、Thunderbird で一時的な拡張機能を読み込むには、次の手順を使います。

1. Thunderbird を起動する
2. 右上またはメニュー内のアプリケーションメニューから「アドオンとテーマ」または「Add-ons and Themes」を開く
3. 左側で「拡張機能」または「Extensions」を選ぶ
4. 右上の歯車アイコンを押す
5. 「デバッグ用アドオン」または「Debug Add-ons」を選ぶ
6. 「Load Temporary Add-on...」または「一時的なアドオンを読み込む」を選ぶ
7. このワークスペース内の `manifest.json` を選択する
8. 一時的なアドオンとして読み込まれることを確認する

### 確認のポイント

- いわゆる `about:debugging` ではなく、Add-ons Manager の gear メニューからのアプローチが現行手順です
- 画面名はバージョンによって異なるため、メニューを見つけられない場合は「アドオンとテーマ」→「拡張機能」→「歯車」→「デバッグ用アドオン」を意識して確認します
- 読み込み対象は `manifest.json` を直接選択します

> 現状の Docs では、拡張機能の読み込みは「Add-ons Manager → Extensions → gear → Debug Add-ons → Load Temporary Add-on...」が正しい流れです。

## command キー定義に関する注意

MDN の公式仕様では、`commands.suggested_key.default` の key は、文字 `A`–`Z` や `0`–`9`、`F1`–`F12`、`Comma`、`Period` などの定義済みキーに限定されます。

そのため、`?` や `/` は manifest で直接指定できません。

- ユーザー体感: `Ctrl + ?` を想定していたが Thunderbird 側で設定不可
- 実際の既定値: `Ctrl+Shift+H`

このため、本実装では `Ctrl + ?` ではなく、Thunderbird で確実に扱える `Ctrl+Shift+H` を既定値に採用しています。

UI 上では「`Ctrl + ?` を表示する」ことは可能ですが、実際のshortcut定義は `?` や `/` を使わない設計にするのが正式です。将来的にはユーザーがメニューから変更できる仕組みを検討します。

## 次の開発ステップ

### Step 1: 実行確認用の最小プロトタイプを整える

- Thunderbird での読み込み手順を確認
- `Ctrl+Shift+H` が実際に呼ばれるかを検証

### Step 2: 実際の Thunderbird 画面との接続を確認

- メール一覧画面での動作を確認
- 画面判定が必要な箇所を識別
- 画面種別に応じたデータ切替の設計を整理

### Step 3: 他画面へ広げる

- メッセージ表示
- メール作成
- 共通ショートカット
- 検索とカテゴリ分類の強化

## Windows での確認チェックリスト

- Thunderbird のバージョンがプロトタイプに対して適切か
- 電子メール一覧画面が表示されているか
- `Ctrl+Shift+H` を押したときにダイアログが起動するか
- 検索欄が入力できるか
- `Esc` で閉じられるか
- 画面を閉じた後に元の操作を継続できるか

## 確認してほしいポイント

次の点が確認できれば、開発を進めやすくなります。

- Thunderbird の拡張機能をテストするためのローカル環境の有無
- 実際に拡張機能を読み込める Thunderbird のインストール状況
- どこまでを最初の検証対象にするか

## 制約と今後の懸念

- `Ctrl+Shift+H` が Thunderbird 本体ショートカットと衝突しないかは継続確認が必要
- Thunderbird の API で現在の画面種別を確実に判定できるかは要検証
- 実際の本体ショートカットをどこまで正確に反映するかは、後続の調査が必要

## 推奨される次の作業

- ThunderBird での拡張機能の読み込み方法を確認する
- 実際に `manifest.json` と `background.js` がロード可能な状態か検証する
- その後、メール一覧プロトタイプの UI と動作を調整する

このまま進める場合は、次に「Thunderbird で読み込む最小構成の整備」と「実行確認のための手順整理」を行います。
